## Overview

Todolist is a learning project built on **Spring Boot 4.1.1** and **Java 25**. It exposes a single-user task list over a JSON REST API, backed by an embedded **H2** file database, with interactive documentation through **Swagger UI**.

The code is layered Controller → Service → Repository. JPA entities are never exposed directly; requests and responses use DTOs. Tasks can be created, renamed, completed, uncompleted, filtered by status, and deleted. There is no authentication or multi-user support.

## Features

- **Task CRUD** — create, read, update, and delete Tasks through the REST API.
- **Complete / uncomplete** — toggle `completed`; there is no partial state.
- **Status filter** — `all` (default), `active`, or `completed`.
- **Newest first** — lists sort by `createdAt` descending, then `id` descending.
- **Request validation** — `POST /tasks` requires a non-blank `title`; otherwise it returns `400 Bad Request`.
- **RFC 7807 errors** — every error uses `application/problem+json`.
- **OpenAPI docs** — generated by springdoc-openapi and served in Swagger UI.
- **Persistent storage** — H2 file database at `./data/todolist.mv.db`.
- **Optional sample data** — seeds five Tasks on startup when the table is empty.
- **Integration tests** — 16 tests exercise the HTTP surface with MockMvc.

## Configuration

Settings live in `src/main/resources/application.properties`:

| Property | Default | Purpose |
| --- | --- | --- |
| `spring.application.name` | `todolist` | Application name |
| `spring.datasource.url` | `jdbc:h2:file:./data/todolist;DB_CLOSE_ON_EXIT=FALSE` | H2 file database location |
| `spring.datasource.username` | `sa` | Database user |
| `spring.datasource.password` | *(empty)* | Database password |
| `spring.jpa.hibernate.ddl-auto` | `update` | Create/update the schema from entities |
| `todolist.seed-sample-data` | `true` | Seed five Tasks on startup if the table is empty |

Tests use `src/test/resources/application.properties`, which switches to an **in-memory** H2 database with `ddl-auto=create-drop`, so they never touch the file database.

With seeding enabled, the app inserts five Tasks when `tasks` is empty: Buy groceries, Walk the dog, Read a chapter of a book, Call mom, and Write the report. Restarting never duplicates them.

To start without sample data:

```bash
./mvnw spring-boot:run -Dspring-boot.run.arguments=--todolist.seed-sample-data=false
```

## Getting started

Requirements: **JDK 25+**. No standalone Maven installation is needed — the included `./mvnw` wrapper handles it — and no database server is needed because H2 is embedded.

```bash
java -version     # should report 25.x
git clone https://github.com/NetParamad/learn-spring-boot-todolist.git
cd learn-spring-boot-todolist
./mvnw spring-boot:run
```

The API is served at **http://localhost:8080**; quick smoke test: `curl http://localhost:8080/tasks`.

Build a runnable jar:

```bash
./mvnw clean package
java -jar target/demo-0.0.1-SNAPSHOT.jar
```

### Scripts

| Command | Description |
| --- | --- |
| `./mvnw spring-boot:run` | Run the app on port 8080 |
| `./mvnw test` | Run the 16 integration tests on in-memory H2 |
| `./mvnw clean package` | Build the jar and run tests |
| `./mvnw clean package -DskipTests` | Build the jar without tests |
| `./mvnw spring-boot:run -Dspring-boot.run.arguments=--todolist.seed-sample-data=false` | Run without sample data |

## Usage

Base URL: `http://localhost:8080`

### Endpoints

| Method | Path | Success | Errors |
| --- | --- | --- | --- |
| `POST` | `/tasks` | `201 Created` | `400` |
| `GET` | `/tasks?status=all\|active\|completed` | `200 OK` | — |
| `GET` | `/tasks/{id}` | `200 OK` | `404` |
| `PATCH` | `/tasks/{id}` | `200 OK` | `400`, `404` |
| `DELETE` | `/tasks/{id}` | `204 No Content` | `404` |

A Task is returned as JSON:

```json
{ "id": 1, "title": "Buy milk", "completed": false, "createdAt": "2026-10-17T16:40:34.714212Z" }
```

1. **Create a Task** — `title` is required and must not be blank. A successful request returns `201 Created` with a `Location` header.

   ```bash
   curl -i -X POST http://localhost:8080/tasks \
     -H 'Content-Type: application/json' \
     -d '{"title": "Buy milk"}'
   ```

2. **List and filter** — the default `status=all` returns every Task, newest first. Use `active` or `completed` to filter.

   ```bash
   curl http://localhost:8080/tasks
   curl "http://localhost:8080/tasks?status=active"
   ```

3. **Read one Task** — `GET /tasks/{id}` returns the Task or `404 Not Found` (`curl http://localhost:8080/tasks/1`).

4. **Update or complete** — `PATCH` accepts `title`, `completed`, or both. Omitted fields stay unchanged.

   ```bash
   curl -X PATCH http://localhost:8080/tasks/1 \
     -H 'Content-Type: application/json' \
     -d '{"completed": true}'
   ```

5. **Delete a Task** — returns `204 No Content`, or `404` when the Task does not exist.

   ```bash
   curl -i -X DELETE http://localhost:8080/tasks/1
   ```

6. **Explore the API** — open Swagger UI at `http://localhost:8080/swagger-ui/index.html`; the OpenAPI JSON is at `http://localhost:8080/v3/api-docs`.

All errors use **RFC 7807 Problem Details**:

```json
{ "detail": "Task 999 not found", "instance": "/tasks/999", "status": 404, "title": "Not Found" }
```

Validation failures return `400` with `"detail": "Validation failed"`.

## Notes

- **Domain language** — [`CONTEXT.md`](CONTEXT.md) defines **Task** (avoid *Todo, item, note, entry*) and **Completed** (no partial state).
- **Persistence** — the schema is managed by Hibernate (`ddl-auto=update`); there is no migration tool. Stop the app and delete `data/` to reset all data.
- **Single instance** — the H2 file database can be opened by only one process at a time. If an old instance holds the lock, stop it before starting another.
- **Port conflicts** — if port 8080 is busy, append `--server.port=9090` to `spring-boot.run.arguments`.
- **Environment** — no environment variables are required; settings come from `application.properties` or command-line overrides.
